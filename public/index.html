Race archive

Record on race day, cut Hub-named clips at the end of the day, then search this Drive. Press Record on Broadcast before the first race. After racing, copy camera files into incoming\vmix, start-cam, barge, and drone, then on the graphics PC run npm run archive:ingest -- --incoming "D:\AHD\{regatta}\{date}\incoming" (add --apply to write the cuts). Copy the hub folder to Drive overnight. Sign in below to find those files by athlete, race, event, or year. After a search, use Hub video to pick the RowIT auto-name (e.g. NZCC W_Snr_8+ 18-02-2026) and jump to that clip.

Race-day recording and ingest

On the graphics PC, keep the local hub running and bookmark http://localhost:3000/race-day-record.html. Press Record there, or on Broadcast, before the first race. Draw, Results, and live-race stepping on that page (or the hub, or the vMix overlay keys) all write the same log.

What each race stores

Draw (D) is the start — not the daysheet clock. The daysheet time is the plan; the Draw press is when that race actually went to air. The recorder snapshots RowIT at that moment: race label, event, round, lane draw, and competitor names.

Results (R) is the end, and it attaches official placings when the results sheet is up. Some races never get a Results graphic. In that case the next Draw closes the previous race (endedBy: next-draw) and opens the new one. Step the live race with + before that next Draw so the new window is the next race. A second Draw on the same race does not start a new window.

If Results is not published yet, the race still closes with the draw and crews, marked no results sheet.

Rowing Hub names

The ingest script names each cut like this (no extension needed in the workflow):

(Regatta) (Event_with_underscores) (day-month-year)
Example: NZCC W_Snr_8+ 18-02-2026

Heats and other non-finals add Race 52 so two races of the same event on the same day do not collide. A finals keep the short Hub title. The recorder writes that title, plus a description of crews and athletes:

DUAC 2, WKOC 1|Charlotte Crosbie, Perri Stevenson

Crews (comma-separated) sit before the pipe; athlete names after it. Tick Cameras rolling on the recorder so each cut is labelled Stream (PGM with graphics and audio), Start cam, Barge, Drone, Podium, Slow motion, or Other. Stream uses the Hub title as-is; the other cameras append the camera name, e.g. NZCC W_Snr_8+ 18-02-2026 Start cam.

The log file

Written live to public/data/race-cues/{regatta}/{yyyy-mm-dd}.json (NZ date). Copy that file with the video at end of day. Keep it on the PC until the day is safely in Drive — Drive must not be the only copy.

Clocks

A minute of drift puts a clip on the wrong race.

  • Graphics / vMix PC: NTP, always. The cue times come from this clock.
  • Cameras: set from that PC (or a GPS camera) at briefing, then leave them.
  • Check drift once at lunch.

During the day

Keep racing simple: continuous (or long-take) ISOs in vMix, cameras onto SD cards. Do not start/stop every race unless you have a spare operator — a missed record-start costs more than extra file size. Leave camera filenames as they are (C0001.MP4 is fine). The ingest script matches times and names the Hub cuts.

End of day

  1. Copy SD cards and vMix files onto the recorder disk first, not straight to Drive: D:\AHD\{regatta}\{date}\incoming\vmix\, …\incoming\start-cam\, …\incoming\barge\, …\incoming\drone\. Copy the day’s race-cues JSON next to them.
  2. On the graphics PC (ffmpeg on PATH), dry-run then cut Hub-named clips: 
    npm run archive:ingest -- --incoming "D:\AHD\nzcc\2026-02-18\incoming"
npm run archive:ingest -- --incoming "D:\AHD\nzcc\2026-02-18\incoming" --apply
    The script matches each file’s start + duration to Draw → end (plus 30s preroll and 60s tail) and writes named files into …\{date}\hub\. Add --offset-start-cam 12 if an SD card clock is 12 seconds slow.
  3. Overnight, copy that hub folder (and the cue JSON) into the AHD Drive date folder. Archive search is read-only — it does not upload.

vMix files usually match easily (PC clock). SD cards are the ones that need the cue log and a clock check. Same ingest for both. Cuts use ffmpeg stream-copy, so they land on keyframes (typically a second or two off). Use --accurate if you need it tighter.

Drive folders

Keep a date folder, then store the Hub-named cuts (camera in the filename):

AHD Drive / NZCC / 2026-02-18 /
  NZCC W_Snr_8+ 18-02-2026
  NZCC W_Snr_8+ 18-02-2026 Start cam
  NZCC W_Snr_8+ 18-02-2026 Barge
  NZCC W_Snr_8+ 18-02-2026 Drone
  2026-02-18.json

Paste the Hub description on the Stream file. Keep original camera names in a sidecar if you still have the SD card IDs. Athlete/race search from the daysheets will match the event slug and date in that title.
