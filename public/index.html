Race-day recording and ingest

On the graphics PC, keep the local hub running and bookmark http://localhost:3000/race-day-record.html. Press Record there, or on Broadcast, before the first race. Draw, Results, and live-race stepping on that page (or the hub, or the vMix overlay keys) all write the same log.

What each race stores

Draw (D) is the start — not the daysheet clock. The daysheet time is the plan; the Draw press is when that race actually went to air. The recorder snapshots RowIT at that moment: race label, event, round, lane draw, and competitor names.

Results (R) is the end, and it attaches official placings when the results sheet is up. Some races never get a Results graphic. In that case the next Draw closes the previous race (endedBy: next-draw) and opens the new one. Step the live race with + before that next Draw so the new window is the next race. A second Draw on the same race does not start a new window.

If Results is not published yet, the race still closes with the draw and crews, marked no results sheet.

The log file

Written live to public/data/race-cues/{regatta}/{yyyy-mm-dd}.json (NZ date). Copy that file with the video at end of day. Keep it on the PC until the day is safely in Drive — Drive must not be the only copy.

Clocks

A minute of drift puts a clip on the wrong race.

  • Graphics / vMix PC: NTP, always. The cue times come from this clock.
  • Cameras: set from that PC (or a GPS camera) at briefing, then leave them.
  • Check drift once at lunch.

During the day

Keep racing simple: continuous (or long-take) ISOs in vMix, cameras onto SD cards. Do not start/stop every race unless you have a spare operator — a missed record-start costs more than extra file size. Leave camera filenames as they are (C0001.MP4 is fine). Indexing is a sidecar job, not a rename-in-the-field job.

End of day

  1. Copy SD cards and vMix files onto the recorder disk first, not straight to Drive: D:\AHD\{regatta}\{date}\incoming\vmix\ and …\incoming\cam-a\ etc. Copy the day’s race-cues JSON next to them.
  2. Match each file’s start time + duration against the log. Overlap with draw → end (Results, or the next Draw), plus about 30s preroll and a minute of tail, tags that file to that race.
  3. Write a sidecar next to the file, or one index.json for the day, then upload.

vMix files usually match easily (PC clock). SD cards are the ones that need the cue log and the clock check. Same index for both.

Drive folders

Use race-aware folders so this archive page can find them later:

AHD Drive / Maadi 2026 / 2026-03-23 / Race 012 B U15 2X heat /
  vmix-pgm.mp4
  vmix-iso2.mp4
  cam-a.mp4
  2026-03-23.json

Keep original camera names in the sidecar. The folder and race label are what people (and athlete/race search from the daysheets) will find. Put a copy of that day’s race-cues JSON in the date folder as well.

Storage

  • Race day working set: fast local disk on the graphics PC. Do not upload while you are still racing unless you have a spare NIC and a quiet window.
  • Archive: this Shared Drive, overnight, after files are tagged.
